# 产品范围

## 产品定位

本项目帮助企业维护可信的客服知识，并使用可追溯的依据回答客户问题。后续里程碑会将智能客服连接到受控的业务工具和人工客服流程。

## 参与者

### 企业管理员

- 创建并管理企业工作空间。
- 上传、处理和发布知识文档。
- 撤回已经失效的知识。
- 查看文档处理失败和回答引用情况。

### 客户

- 提出客服问题。
- 获得有依据的回答，或者明确的无法回答结果。
- 自动化无法解决时可以转交人工客服。

### 人工客服

- 在后续里程碑中接收升级的客户会话。
- 查看对话摘要、知识依据和已经完成的工具操作。
- 在不丢失已验证上下文的前提下继续处理会话。

## 第一条业务闭环

1. 已认证的企业管理员上传一份客服政策文档。
2. 平台将文档处理成可以检索的知识。
3. 管理员显式发布已经处理完成的版本。
4. 同一租户的客户提出相关问题。
5. 平台只检索该租户有权使用的当前有效知识。
6. 平台返回带来源引用的回答；依据不足时明确返回无法回答。

## 正确性约束

1. 一个租户绝不能检索或引用另一个租户的数据。
2. 草稿、处理失败、已替换和已撤回的文档版本不能用于客户回答。
3. 事实性回答必须保存支撑它的来源片段。
4. 缺少依据、检索失败和模型失败是三种不同结果，不能合并成一条模糊错误。
5. 新文档版本完成处理并成功原子发布前，不能替换当前有效版本。
6. 不能因为模型生成的文本要求执行某项操作，就直接执行订单、退款等业务动作。

## 第一阶段验收标准

- 管理员能够创建、处理、发布、替换和撤回文档版本。
- 同一租户的查询可以检索当前有效版本的知识片段。
- 跨租户和无效版本的检索得不到数据。
- 回答能够记录所使用的知识片段引用。
- 依据不足时产生确定的无法回答结果。
- 文档处理和模型服务失败能够区分是否允许重试。
- 自动化测试覆盖正常、边界和失败行为。

## 第一阶段不做的内容

- 语音或电话客服
- 自动退款、取消订单或支付
- 从零训练基础大模型
- 多智能体编排
- 移动端应用
- Kubernetes 部署
- 宣称生产流量、准确率、节省成本或业务收益
